# CepArsiv — Uygulama Planı (v2, onaylı)

> **For agentic workers:** Implement task-by-task. Steps use checkbox (`- [ ]`) syntax. Sıra zorunlu: önce RED test → kırmızıyı doğrula → onay → implementasyon → yeşili doğrula → commit. Testi olmayan kod commit edilmez.

**Goal:** SQLite + FastAPI + Jinja2/HTMX tabanlı, tek process çalışan, telefon dostu kişisel bilgi arşivi (not/yer imi/snippet, tag, FTS, REST API, export/import, audit log).

**Architecture:** Tek FastAPI process (uvicorn, 1 worker), tek SQLite dosyası (WAL), server-side render; build pipeline ve harici servis yok.

**Tech Stack:** Python 3, FastAPI, SQLModel, SQLite+FTS5, Jinja2, HTMX, PicoCSS, markdown-it-py, pytest+httpx.

## Teknik Mimari

```
[Tarayıcı / curl]
      │  HTTP (127.0.0.1:8000)
      ▼
FastAPI app (tek process, tek worker)
 ├─ Web routers (/)          ── Jinja2 + HTMX, session cookie
 ├─ API routers (/api/v1)    ── JSON, Bearer token
 ├─ deps: get_current_user, get_api_user, get_session
 ├─ services/ (auth, items, tags, search, tokens, dataport, audit)
 ├─ models (SQLModel) ── SQLAlchemy engine ──► SQLite (WAL)
 └─ static/ (pico.min.css, htmx.min.js — vendor, CDN yok)
```

Katmanlar: `routers` yalnızca HTTP (doğrulama, render, yönlendirme) → `services` iş mantığı/sorgular → `models` şema → `templates` sunuş. Router'dan SQL yazılmaz.

Veri akışı (web): Form POST → CSRF kontrolü → service → audit → redirect/partial. (API): Bearer → token hash doğrulama → service → JSON.

## Veritabanı Tasarımı

| Tablo | Alanlar | Not |
|---|---|---|
| `users` | id PK, username UNIQUE, password_hash, created_at | PBKDF2-SHA256, tuz `secrets.token_hex(16)` |
| `sessions` | id PK (token str), user_id FK, created_at, expires_at, ip | sunucu taraflı iptal |
| `items` | id PK, user_id FK, type, title, slug, body, url NULL, is_favorite, is_archived, is_deleted, created_at, updated_at | `UNIQUE(user_id, slug)`, soft delete |
| `tags` | id PK, user_id FK, name | `UNIQUE(user_id, name)`, lowercase normalize |
| `item_tags` | item_id FK, tag_id FK, PK(item_id, tag_id) | many-to-many |
| `api_tokens` | id PK, user_id FK, name, token_hash UNIQUE, prefix, last_seen_at NULL, created_at, expires_at NULL | ham token yalnızca oluşturma anında |
| `audit_log` | id PK, user_id NULL, action, entity_type NULL, entity_id NULL, detail, ip NULL, created_at | append-only |
| `items_fts` | FTS5 virtual table | external-content, aşağıda |

İndeksler: `ix_items_user_deleted_created(user_id, is_deleted, created_at DESC)`, `ix_items_user_type(user_id, type)`, `ix_item_tags_tag(tag_id)`, `ix_api_tokens_hash`, `ix_audit_user_created`, `ix_sessions_expires`.

FTS5: `CREATE VIRTUAL TABLE items_fts USING fts5(title, body, content='items', content_rowid='id', tokenize='unicode61');` + INSERT/UPDATE/DELETE trigger'ları SQLite resmi external-content kalıbına birebir uygun. Arama: `JOIN items ON items.id = items_fts.rowid WHERE items_fts MATCH ?` + kullanıcı/filtre koşulları JOIN tarafında. FTS5 yoksa LIKE fallback. Yeniden inşa: `INSERT INTO items_fts(items_fts) VALUES('rebuild')` (import sonrası). MATCH girdisi builder'dan geçer (terimler tek tek çift tırnak, AND); ham kullanıcı metni sorguya girmez.

PRAGMA (her bağlantıda): `journal_mode=WAL`, `synchronous=NORMAL`, `foreign_keys=ON`, `busy_timeout=5000`, `cache_size=-2000`.

## Güvenlik Planı

PBKDF2-SHA256 (tuz 16B, ITER>=200000, compare_digest) — bcrypt/argon2 bilinçli yok (derleme riski). Session: DB tablosu, opaque `token_urlsafe(32)`, HttpOnly+SameSite=Strict (Secure yalnızca HTTPS varsa), 24 saat mutlak süre, login anında lazy temizlik. CSRF: session bağlı rastgele form tokenı tüm web mutasyonlarında; API Bearer kullandığı için gerekmez. Token: SHA-256 hash DB'de, ham değer bir kez yanıtta. XSS: markdown html passthrough kapalı, Jinja2 autoescape açık, `|safe` yalnızca render_markdown. SQLi: yalnızca parametreli sorgu. Import limitleri §E2. DEBUG=0; production'da traceback dönmez.

## Performans Planı

WAL + synchronous=NORMAL + cache ~2MB + busy_timeout. Tek worker. Sayfalama her listede zorunlu (20; API limit ≤100). Toplam COUNT yok → (items, has_next) modeli. FTS5 MATCH; LIKE yalnızca fallback. Ağır job yok; export senkron tek seferlik; session temizliği lazy. Telefonda: sunucu kapalıyken uvicorn'u öldür, termux-wake-lock yalnızca açıkken, DB iç depolamada, büyük import şarjda.
